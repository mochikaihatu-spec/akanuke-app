# 無料/有料プランと AI 利用制限の設計(2026-10-28)

## 方針(ユーザー指定)
| | 無料 | 有料(案・検証用) |
|---|---|---|
| 料金 | 0円 | 月額680円(**決済は未実装**。UI では「準備中」と明記) |
| 垢抜けプラン作成(再作成を含む) | 月1回 | 月4回 |
| AI美容相談 | 月20回 | 月100回 |
| プランの閲覧・進捗管理 | 可 | 可 |
| チャット / 今日のToDo / 写真解析(方針に記載なし) | 1日 20 / 5 / 10 回(従来どおり) | 同じ(要検討) |

数字はすべて `src/lib/plans-config.ts` の `AI_QUOTAS` / `PAID_PLAN` で変更できる。

## 仕組み
- **回数の管理はサーバー(DB)側**。リロード・ログアウトでリセットされない。日本時間(Asia/Tokyo)で、月制限は毎月1日0時、日制限は毎日0時に切り替わる。機能ごとに独立して数える(`ai_usage` の `usage_date` は期間の開始日、`kind` は機能名)。
- **失敗は数えない**: `begin_ai_request`(鍵を取る+今期の回数を確認。ここでは減らさない)→ AI 呼び出し → `finish_ai_request`(成功したときだけ +1、成功・失敗とも `ai_usage_logs` にトークン数を記録、鍵を返す)。
- **回避されない理由**: 鍵(token)は API サーバーだけが持ち、クライアントには渡らない。ユーザーが DB 関数を直接呼んでも、増やせるのは自分の回数だけ(AI は呼べない)。他人の鍵は返せない。同時実行は鍵で直列化されるので、上限を超えて通る隙間がない。鍵の期限切れ後に成功を報告された場合も回数は数える。
- **有料判定**: `subscriptions` 表(`status='active'` かつ `current_period_end` が未来)だけが有料。ユーザーは読み取りのみ(書込みポリシーなし)。行がない/読めない/期限切れ = 無料(安全側)。決済連携は未実装で、現状は SQL Editor で手動追加した行だけが有料になる。
- **上限到達時**: 429 と、上限の回数・リセット時期・(有料の案内が意味を持つ機能だけ)有料プランの案内を日本語で返す。画面側は `/api/usage`(AI を呼ばない)で残り回数を表示し、プラン作成が 0 回ならボタンを無効化。
- **コスト対策**: 各 AI 呼び出しは 1 通のメッセージのみ(会話履歴は送らない)。入力サイズに上限あり。機能ごとのモデル・`max_tokens`・thinking の有無は `src/lib/ai-config.ts` で独立に設定。鍵は `NEXT_PUBLIC_` を付けずサーバー側のみ。

## 今後
- 決済(Stripe 等)を入れるときは、webhook で `subscriptions` を更新する(サービスロールキーはサーバー専用の環境変数)。
- 有料限定機能は `TIER_FEATURES` を足場に、API 側で `getTier()` を見て判定する。
- 他の AI 機能(todos / chat / photo)の thinking 無効化・モデル変更は、品質を見て `ai-config.ts` で調整できる。
