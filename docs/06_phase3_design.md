# フェーズ3 設計: AI 相談でプランを調整(承認制)(2026-10-28 承認)

## 方針
- **承認するまでプランは1文字も変わらない**。AI は「差分(どこをどう変えるか)」だけを返し、アプリが検査して変更前/変更後を見せる。
- 調整は **1回で完結**(相談 → 提案 → 承認 or やめる)。会話履歴は持たない(安く・安全)。
- 承認すると新しいプランとして保存し、元は履歴に残る。**「何日目か」のサイクルは引き継ぐ**(`plans.cycle_start`)。ミッションの記録もそのまま残る。
- 承認の処理は AI を使わない(料金・回数なし)。

## 回数(案A・承認済み)
- 小さな調整(相談 → 提案)は専用の **`plan_adjust`**: 無料 月5回 / 有料 月20回。失敗は数えない(これまでと同じ `begin_ai_request` / `finish_ai_request`)。
- 全面的な作り直し(ヒアリングからのプラン再作成)は従来どおり **`plan`**: 無料 月1回 / 有料 月4回。
- 調整できる範囲: 行動の差し替え・追加・削除、週間プランの特定の日の差し替え、頻度・時間・費用の変更。取り組む部位そのものの入れ替えや憧れの変更は「作り直し」。

## AI が返す差分(patch)
```
{ "message": "ひと言(120文字以内)",
  "changes": [0〜6件]
   { "op": "replace_action", "element": 0, "action_index": 1, "action": {title, detail, minutes, cost_yen, frequency} }
   { "op": "add_action",     "element": 0, "action": {...} }
   { "op": "remove_action",  "element": 0, "action_index": 1 }
   { "op": "replace_weekly", "day": 3, "area": "肌", "task": "...", "minutes": 5 } }
```
- 変更が0件(医療が必要そう等)のときは、ひと言だけ返し、調整案は保存しない。
- アプリは patch を複製したプランに適用 → `validatePlan` で検査(許可外の部位・件数・数値は拒否/切り詰め)→ 変更前後の差分(`diffPlans`)を作る。予算・時間を超える場合は注意書きを出す(止めはしない)。

## データ(016)
- `plans`: `cycle_start`(1日目の日付・日本時間。既存は作成日で補完)、`parent_id`、`change_note` を追加。
- `plan_proposals`: 調整案(`pending` / `applied` / `dismissed`)、`patch`、`diff`(表示用)。RLS: 自分の行だけ、`plan_id` も自分のプランのみ。
- `save_adjusted_plan(proposal_id, content, note)`: 調整案が承認待ちで、対象プランが今も使用中のときだけ、元を archived にして新しいプランを追加(cycle_start を引き継ぐ)。古い案・適用済み・やめた案は拒否。

## API / 画面
- `POST /api/plan/adjust`: 相談文(500文字まで)→ AI → 検査 → `plan_proposals` に保存して返す。AI に渡すのは、現在のプラン・ヒアリングの答え・直近14日のミッション集計・相談文だけ。
- `POST /api/plan/apply`: 調整案 ID → 保存済み patch を使用中プランに再適用 → 検査 → `save_adjusted_plan`。AI なし。
- `/plan/consult`: 相談 → 調整案(変更前/後・注意書き)→ 「この内容で変更する」/「やめる」/「もう一度相談する」。マイプランとホームのミッションからリンク。
