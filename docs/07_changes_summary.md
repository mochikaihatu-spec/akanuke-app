# アカヌケ 変更のまとめ(2026-10-25 〜 10-28)

「ダイエット・美容の記録アプリ」を、新しいコンセプト **「憧れを、あなた専用の行動プランに。」** に向けて作り替えながら、公開前に必要な安全対策を整えた期間のまとめです。すべて本番(Vercel)に反映済みです。

## 1. はじめにわかったこと(調査)
- PHP は使っていないので、PHP の脆弱性は関係ありませんでした。
- ログインとデータの分離は、すでに実装・公開済みでした(以前の作業)。
- 足りなかったもの: AI の利用回数制限、入力の長さ制限、AI の安全ルール、Next.js の既知の脆弱性への対応、規約・ポリシー、アカウント削除。
- 詳細は `docs/01_investigation.md`、計画は `docs/02_roadmap.md`。

## 2. 公開前の安全対策(フェーズ0)
| 内容 | ポイント |
|---|---|
| AI の利用制限と安全ルール | 回数制限、入力サイズの上限、API 側のログイン確認、全プロンプトに共通の安全ルール(整形・医療の推奨禁止、診断禁止、容姿の採点禁止、実在人物との類似の約束禁止、極端な食事制限禁止)。 |
| Next.js の更新 | 16.3.2 → 16.4.3(`sharp` も 0.35.5 に)。公式の脆弱性情報9件のうち、このアプリに当てはまるのは未確認の2件だけで、更新で全部解消。 |
| キーの管理 | Anthropic のキーを再発行して旧キーを削除。使っていなかった Notion の環境変数を Vercel から削除。 |
| セキュリティヘッダー | CSP(通信先をアプリ自身と Supabase に限定)、iframe 禁止、nosniff、HSTS など。ESLint エラーも 0 件に。 |

| 不具合の修正 | AI の答えが途中で切れる問題(「考える」文章が上限を食っていた)を修正。 |

## 3. 新コンセプトの機能(フェーズ1〜3)
1. **ヒアリング(`/onboarding`)**: 憧れの雰囲気、取り組みたい部分、悩み、予算、使える時間、好みを入力。
2. **プラン生成**: AI が JSON でプランを返し、アプリが形を検査してから保存(要約・雰囲気キーワード・部位ごとの優先順位と行動・費用の合計・7日分の週間プラン)。
3. **マイプラン(`/plan`)**: 保存したプランを再表示。作り直すと前のプランは履歴に残る。
4. **今日のミッション**: 週間プランから日本時間で「何日目か」を計算し、毎日1つ表示。AI は使わない。「完了」「お休み」「戻す」、今週の進み具合、連続日数、部位別の回数。責めない設計(お休みは連続を途切れさせない)。
5. **AI 相談でプラン調整(`/plan/consult`)**: 相談すると AI が「どこをどう変えるか」の案を出し、変更前/後を並べて表示。**承認するまでプランは変わらない**。承認すると新しいプランとして保存(元は履歴、「何日目か」は継続)。予算・時間を超える場合は注意書き。

## 4. 無料・有料プランと利用制限
| | 無料 | 有料(案・検証用。月680円) |
|---|---|---|
| プラン作成 | 月1回 | 月4回 |
| プラン相談(調整) | 月5回 | 月20回 |
| AI 美容相談 | 月20回 | 月100回 |
| チャット / ToDo | 1日 20 / 5 回 | 同じ |
| 食事の写真解析 | 月3回 | 1日5回(2026-10-29 変更) |

- 数字は `src/lib/plans-config.ts` で変更できます。
- 日本時間で月初(日は0時)にリセット。リロードやログアウトでは戻りません。
- **AI の回答に失敗したときは回数に数えません**(「確認 → AI 呼び出し → 成功したときだけ加算」。同時実行は鍵で防ぐ)。
- 上限に達したら、残り回数とリセット時期を表示。有料プランの案内は控えめに一文だけ。
- **決済は未実装**です。画面では「準備中」と明記し、購入できるようには見せていません。有料かどうかは `subscriptions` 表(ユーザーは読むだけ)で、サーバー側が判定します。
- トークン数を `ai_usage_logs` に記録。機能ごとのモデル・上限・処理方法は `src/lib/ai-config.ts`。
